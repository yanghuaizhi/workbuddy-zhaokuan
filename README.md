# 找款助手

店主在腾讯 WorkBuddy 里发一张商品图，找到搜款网上的相似货源，再说一句话就能在结果里收窄。

目标是上架可用，不是 Demo。

## 现在到哪

```mermaid
flowchart LR
    subgraph V["路径已验证"]
        V1["传本地图搜出结果"]
        V2["再说一句话二次筛选"]
        V3["候选带真实价格"]
    end
    subgraph H["做了一半"]
        H1["会话原生怎么呈现<br/>还没有观察到"]
    end
    subgraph N["还没开始"]
        N1["信用与发货表现进排序"]
        N2["公网部署与限流对齐"]
        N3["平台上架审核"]
    end
    V --> H --> N --> G(["上架可用"])
    style V fill:#d4edda,stroke:#28a745
    style H fill:#fff3cd,stroke:#ffc107
    style N fill:#f8d7da,stroke:#dc3545
```

「路径已验证」指技术路径确认走得通，不代表交付件已就绪。服务当前只跑在一台本机上。

## 谁负责什么

按数据流切两刀，三个人各拿一段。

```mermaid
flowchart LR
    IN["店主的图 / 话"] --> T["terence<br/>输入端"]
    T -->|"规范化搜索请求"| Z["正耀<br/>服务端与上游"]
    Z -->|"原始候选列表"| H["怀志<br/>呈现输出端"]
    H --> OUT["店主看见的表格"]
    style T fill:#e8f4f8,stroke:#0288d1
    style Z fill:#f3e5f5,stroke:#7b1fa2
    style H fill:#e8f5e9,stroke:#388e3c
```

| 人 | 那一段做什么 |
|---|---|
| terence | 图片进入通道、入参解析、条件映射、工具描述 |
| 正耀 | 服务骨架、三条上游对接、候选映射、部署与限流 |
| 怀志 | 候选整理、排序、表格渲染、渲染实测、Expert 包与上架 |

边界是两个交接的数据结构，不是职能——各段可以独立开发、用假数据独立测试。详见 [分工与职责](00-团队协作/分工与职责.md)。
