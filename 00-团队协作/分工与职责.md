# 分工与职责

按数据流切两刀，三个人各拿一段。边界是数据结构，不是职能——各段可以独立开发、用假数据独立测试。

## 三段与两个交接物

```mermaid

    IN["店主的图 / 话"] --> T["terence<br/>输入端"]
    T -->|"交接物一<br/>规范化搜索请求"| Z["正耀<br/>服务端与上游"]
    Z -->|"交接物二<br/>原始候选列表"| H["怀志<br/>呈现输出端"]
    H --> OUT["店主看见的表格"]
    style T fill:#e8f4f8,stroke:#0288d1
    style Z fill:#f3e5f5,stroke:#7b1fa2
    style H fill:#e8f5e9,stroke:#388e3c
```

| 交接物 | 内容 | 定下来之后 |
|---|---|---|
| 规范化搜索请求 | 图片地址或关键词、市场、筛选条件 | terence 与正耀各自独立开发 |
| 原始候选列表 | 上游原始候选，未去广告、未去重、未排序 | 正耀与怀志各自独立开发 |

两个交接物是三人的接口，变更走决策记录，不口头改。

## terence · 输入端

从店主的图和话，到一个规范化的搜索请求。

| 交付 | 内容 |
|---|---|
| 凭证签发 | `create_image_upload`：签名算出来不落库，返回上传地址，五分钟有效 |
| 上传通道 | `POST /upload/v1`：先验签名再验过期，体积上限 20 MB |
| 图片规整 | 统一成 JPEG、长宽 100 到 4096；太小或太大当场告诉店主改哪里 |
| 凭证复用 | 同一张凭证在有效期内被重复使用的处理方式，当前未闭合 |
| 入参解析 | 两个找款工具的入参解析成规范化搜索请求 |
| 条件映射 | 「只要支持代发的、80 到 120 的」映射成代发标记与价格区间 |
| 市场默认值 | 店主没说市场时默认广州沙河 |
| 工具描述 | 三个工具的描述，让模型在有图时不去调文字找款 |
| 输入侧话术 | 图不合格、上传超时怎么跟店主说 |

整段是纯输入输出：给一个图片字节流还回一个图片地址，给一句话还回一个搜索请求。不碰上游、不碰候选，用假数据能全测完。

## 正耀 · 服务端与上游

从搜索请求，到原始候选列表。

| 交付 | 内容 |
|---|---|
| 服务骨架 | MCP 服务实例、传输层、配置、日志脱敏、健康检查 |
| 上游对接 | 以图找相似款、按关键词找款、图片存进搜款网换取可搜地址 |
| 候选映射 | 上游返回映射成统一的候选结构 |
| 字段策略 | 上游没给的字段就空着，不填一个看起来合理的值 |
| 失败策略 | 不做反复重试，超时或连不上只再试一次 |
| 上线交付 | 生产域名、证书、监控、调用量与限流对齐 |

三条上游全在这条线上。

## 怀志 · 呈现输出端

从原始候选列表，到店主看见的表格。

| 交付 | 内容 |
|---|---|
| 去广告 | 去掉广告位与专题卡片 |
| 去重 | 同一个款只留一条 |
| 排序 | 高信用、发货准时的档口进排序维度 |
| 限量 | 按相似度顺序最多给 20 条 |
| 表格渲染 | 候选表格的列与内容 |
| 缺字段的显示 | 字段空着时怎么显示 |
| 原样转发约束 | 写进 SKILL：表格由服务端渲染，不重排不改写 |
| 渲染形态实测 | 会话里原生怎么呈现，当前未观察到 |
| Expert 包与上架 | 包装配、平台审核、项目管理 |

排序是本期唯一的新增能力，也不是纯实现——相似度与信用怎么权衡是产品判断，排太靠信用会把最像的款挤下去。

## 三条线的对外依赖

| 线 | 关键路径上的未知 | 对外依赖 |
|---|---|---|
| 输入端 | 凭证复用的处理方式 | 无 |
| 服务端与上游 | 部署、限流上限 | 运维、搜款网研发 |
| 呈现输出端 | 会话原生渲染形态、平台审核 | WorkBuddy 平台方 |

输入端对外依赖为零，可以独立闭环推进。
