# 决策记录

## 什么时候写

满足任一条就写：推翻已有前提、在多个方案之间做了选择、约束了后续的实现空间。

不满足就别写，日常实现细节走 Issue。

## 已定的

| 编号 | 决策 | 取舍 |
|---|---|---|
| ADR-001 | 首版不做店主账号登录，三条上游都走不需要登录的公开接口 | 放弃个性化与店主私有数据，换掉整套授权流程的实现与审核成本 |
| ADR-002 | 以图找款是主入口，文字找款是补充与二次筛选 | 女装的版型、面料手感、领口细节用文字描述会失真，店主手上本来就是图。放弃以文字为主入口的设计 |
| ADR-003 | 图片走单独一条上传通道，不塞进工具调用 | 工具调用只能传文字参数，图片进不去。这是协议层的硬约束，不是权限问题。代价是多一次往返 |
| ADR-004 | 候选表格由服务端渲染好，模型原样转发不重排不改写 | 放弃模型按上下文自由发挥的灵活性，换样式可控、口径一致、数字不被改写 |
| ADR-005 | 上游没给的字段就空着，不填一个看起来合理的值 | 放弃表格的视觉整齐，换店主不会照着一个编出来的值去跑档口 |
